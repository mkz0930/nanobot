## 🔑 关键设计模式

### 1. 注册表模式 (Registry Pattern)
**应用**: ToolRegistry, ProviderRegistry

**优点**:
- 集中管理
- 易于扩展
- 避免硬编码

**示例**:
```python
# 注册
registry.register(MyTool())

# 查找
tool = registry.get("my_tool")
```

### 2. 策略模式 (Strategy Pattern)
**应用**: Provider 系统

**优点**:
- 统一接口
- 可替换实现
- 易于测试

### 3. 发布-订阅模式 (Pub-Sub Pattern)
**应用**: MessageBus

**优点**:
- 解耦组件
- 支持异步
- 易于扩展

### 关键问题思考
1. 为什么工具返回字符串而不是结构化数据？
   - LLM 更容易理解自然语言
   - 可以直接作为上下文继续对话
   - 避免序列化问题

2. 为什么使用 Provider Registry 而不是 if-elif？
   - 单一数据源，易于维护
   - 添加新 Provider 不需要修改代码
   - 自动处理环境变量和前缀

3. 为什么技能使用 Markdown 而不是 Python 代码？
   - 更易读、易写、易维护
   - 非技术人员也可以创建
   - 支持渐进式加载

4. 为什么需要消息总线而不是直接调用？
   - 解耦 Channel 和 Agent
   - 支持多个 Channel 同时工作
   - 易于扩展新的 Channel

## 快速入门

### 第一步：安装和配置

```bash
# 克隆仓库
git clone https://github.com/mkz0930/nanobot.git
cd nanobot

# 安装（开发模式）
pip install -e .

# 初始化配置
nanobot onboard
```

配置文件会生成在 `~/.nanobot/config.json`，你需要添加 API 密钥：

```json
{
  "providers": {
    "openrouter": {
      "apiKey": "sk-or-v1-你的密钥"
    }
  },
  "agents": {
    "defaults": {
      "model": "anthropic/claude-opus-4-5"
    }
  }
}
```

### 第二步：第一次对话

```bash
# 单次对话
nanobot agent -m "你好，介绍一下自己"

# 交互模式
nanobot agent
```

### 第三步：连接聊天平台

以 Telegram 为例：

1. 在 Telegram 中找到 @BotFather，创建机器人获取 token
2. 编辑配置文件：

```json
{
  "channels": {
    "telegram": {
      "enabled": true,
      "token": "你的机器人token",
      "allowFrom": ["你的用户ID"]
    }
  }
}
```

3. 启动网关：

```bash
nanobot gateway
```

## 核心概念

### 1. Agent（代理）

Agent 是 nanobot 的核心，负责理解用户意图并执行任务。

**关键文件**：`nanobot/agent/loop.py`

**工作流程**：
```
用户消息 → 消息总线 → Agent Loop → 构建上下文 → 调用 LLM →
执行工具 → 生成响应 → 消息总线 → 用户
```

**核心组件**：
- `ContextBuilder`：构建包含历史、记忆、技能的上下文
- `ToolRegistry`：管理所有可用工具
- `SessionManager`：管理多用户会话
- `SubagentManager`：处理后台任务

### 2. Tools（工具）

工具是 Agent 与外部世界交互的能力。

**工具类型**：
- **文件操作**：`ReadFileTool`、`WriteFileTool`、`EditFileTool`、`ListDirTool`
- **Shell 执行**：`ExecTool`
- **Web 交互**：`WebSearchTool`、`WebFetchTool`
- **消息发送**：`MessageTool`
- **子代理**：`SpawnTool`
- **定时任务**：`CronTool`

**工具结构**（`nanobot/agent/tools/base.py`）：
```python
class Tool(ABC):
    @property
    def name(self) -> str:
        """工具名称"""

    @property
    def description(self) -> str:
        """工具描述"""

    @property
    def parameters(self) -> dict[str, Any]:
        """JSON Schema 参数定义"""

    async def execute(self, **kwargs) -> str:
        """执行工具逻辑"""
```

### 3. Skills（技能）

技能是可加载的知识文档，教会 Agent 如何使用特定工具或完成特定任务。

**技能位置**：
- 内置技能：`nanobot/skills/`
- 用户技能：`~/.nanobot/workspace/skills/`

**技能结构**：
```
skills/
└── github/
    └── SKILL.md  # 技能文档
```

**SKILL.md 格式**：
```markdown
---
name: github
description: "使用 gh CLI 与 GitHub 交互"
metadata: {"nanobot":{"emoji":"🐙","requires":{"bins":["gh"]}}}
---

# GitHub Skill

使用 `gh` CLI 与 GitHub 交互...
```

**技能加载机制**（`nanobot/agent/skills.py`）：
- **Always-loaded skills**：始终加载到上下文
- **Available skills**：仅显示摘要，Agent 按需使用 `read_file` 加载

### 4. Providers（提供商）

Provider 是 LLM 服务提供商的抽象层。

**Provider Registry 模式**（`nanobot/providers/registry.py`）：

所有 Provider 元数据集中管理，添加新 Provider 只需 2 步：

```python
# 步骤 1：在 registry.py 添加 ProviderSpec
ProviderSpec(
    name="myprovider",
    keywords=("myprovider", "mymodel"),
    env_key="MYPROVIDER_API_KEY",
    display_name="My Provider",
    litellm_prefix="myprovider",
    skip_prefixes=("myprovider/",),
)

# 步骤 2：在 config/schema.py 添加配置字段
class ProvidersConfig(BaseModel):
    myprovider: ProviderConfig = ProviderConfig()
```

**支持的 Provider**：
- OpenRouter（推荐，支持所有模型）
- Anthropic、OpenAI、DeepSeek、Gemini
- Moonshot、Zhipu、Qwen、MiniMax
- vLLM（本地部署）

### 5. Channels（频道）

Channel 是与聊天平台的集成。

**支持的平台**：
- Telegram、Discord、WhatsApp
- Feishu（飞书）、DingTalk（钉钉）、Slack
- Mochat、Email、QQ

**Channel 基类**（`nanobot/channels/base.py`）：
```python
class BaseChannel(ABC):
    async def start(self):
        """启动频道"""

    async def stop(self):
        """停止频道"""

    async def send_message(self, chat_id: str, content: str):
        """发送消息"""
```

**连接模式**：
- **WebSocket 长连接**：Feishu、Mochat、DingTalk（无需公网 IP）
- **轮询模式**：Email
- **Bot API**：Telegram、Discord、Slack

### 6. Message Bus（消息总线）

消息总线是事件驱动架构的核心。

**事件类型**（`nanobot/bus/events.py`）：
```python
@dataclass
class InboundMessage:
    """接收的消息"""
    channel: str      # 来源频道
    sender_id: str    # 发送者 ID
    chat_id: str      # 会话 ID
    content: str      # 消息内容
    timestamp: datetime
    media: list[str]  # 媒体文件
    metadata: dict    # 元数据

@dataclass
class OutboundMessage:
    """发送的消息"""
    channel: str
    chat_id: str
    content: str
    reply_to: str | None
```

**消息流**：
```
Channel → InboundMessage → MessageBus → Agent Loop →
OutboundMessage → MessageBus → Channel
```

### 关键设计模式

#### 1. 工具注册模式

所有工具通过 `ToolRegistry` 统一注册和管理：

```python
# 注册工具
registry = ToolRegistry()
registry.register(ReadFileTool())
registry.register(ExecTool())

# 获取工具
tool = registry.get("read_file")

# 执行工具
result = await tool.execute(path="/path/to/file")
```

#### 2. Provider Registry 模式

集中管理 Provider 元数据，避免 if-elif 链：

```python
# 自动匹配 Provider
provider = match_provider_by_model("claude-3-opus")
# → 返回 anthropic provider

# 自动添加前缀
model = apply_prefix("qwen-max", provider_spec)
# → "dashscope/qwen-max"
```

#### 3. 事件驱动架构

Channel 和 Agent 通过消息总线解耦：

```python
# Channel 发布消息
await bus.publish_inbound(InboundMessage(
    channel="telegram",
    sender_id="123",
    chat_id="456",
    content="Hello"
))

# Agent 订阅消息
async for msg in bus.subscribe_inbound():
    response = await agent.process(msg)
    await bus.publish_outbound(response)
```

#### 4. 渐进式技能加载

- **Always-loaded skills**：完整加载到上下文
- **Available skills**：仅显示摘要，Agent 按需加载

这样可以节省 token，同时保持灵活性。

## 开发实践

### 添加新工具

**步骤 1**：创建工具类

```python
# nanobot/agent/tools/mytool.py
from nanobot.agent.tools.base import Tool
from typing import Any

class MyTool(Tool):
    @property
    def name(self) -> str:
        return "my_tool"

    @property
    def description(self) -> str:
        return "这是我的自定义工具"

    @property
    def parameters(self) -> dict[str, Any]:
        return {
            "type": "object",
            "properties": {
                "input": {
                    "type": "string",
                    "description": "输入参数"
                }
            },
            "required": ["input"]
        }

    async def execute(self, **kwargs: Any) -> str:
        input_value = kwargs.get("input")
        # 实现工具逻辑
        result = f"处理结果：{input_value}"
        return result
```

```python
# nanobot/agent/loop.py
def _register_default_tools(self):

    self.tools.register(MyTool())
```

## 进阶主题

### 1. 沙箱模式

生产环境应启用沙箱模式，限制工具访问范围：

```json
{
  "tools": {
    "restrictToWorkspace": true
  }
}
```

启用后：
- 文件工具只能访问 `~/.nanobot/workspace/`
- Shell 工具的路径遍历被阻止
- 提高安全性

### 2. 子代理（Subagent）

子代理用于后台执行长时间任务：

```python
# Agent 可以使用 spawn 工具创建子代理
result = await spawn_tool.execute(
    task="分析大型日志文件",
    background=True
)
```

子代理特点：
- 独立的上下文和会话
- 可以并行执行
- 结果通过消息总线返回

### 3. 记忆系统

记忆系统让 Agent 记住重要信息：

```python
# nanobot/agent/memory.py
class MemoryStore:
    def add_memory(self, key: str, value: str):
        """添加记忆"""

    def get_memory(self, key: str) -> str | None:
        """获取记忆"""

    def get_memory_context(self) -> str:
        """获取完整记忆上下文"""
```

记忆存储在 `~/.nanobot/workspace/memory/`。

### 4. 定时任务

使用 Cron 服务创建定时任务：

```bash
# 添加每日任务
nanobot cron add --name "daily-report" \
  --message "生成每日报告" \
  --cron "0 9 * * *"

# 添加间隔任务
nanobot cron add --name "hourly-check" \
  --message "检查系统状态" \
  --every 3600

# 列出任务
nanobot cron list

# 删除任务
nanobot cron remove <job_id>
```

### 5. 语音转文字

配置 Groq 提供商后，Telegram 语音消息会自动转文字：

```json
{
  "providers": {
    "groq": {
      "apiKey": "your-groq-key"
    }
  }
}
```

### 6. 多模型策略

可以为不同任务配置不同模型：

```json
{
  "agents": {
    "defaults": {
      "model": "anthropic/claude-opus-4-5"
    }
  }
}
```

在代码中动态切换：

```python
# 使用快速模型处理简单任务
response = await provider.complete(
    messages=messages,
    model="anthropic/claude-haiku-4-5"
)
```

### 7. 本地部署

使用 vLLM 运行本地模型：

```bash
# 启动 vLLM 服务器
vllm serve meta-llama/Llama-3.1-8B-Instruct --port 8000
```

配置：

```json
{
  "providers": {
    "vllm": {
      "apiKey": "dummy",
      "apiBase": "http://localhost:8000/v1"
    }
  },
  "agents": {
    "defaults": {
      "model": "meta-llama/Llama-3.1-8B-Instruct"
    }
  }
}
```

## 常见问题

### Q1: 如何调试 Agent 行为？

启用日志模式：

```bash
nanobot agent --logs -m "你的消息"
```

或在代码中配置 loguru：

```python
from loguru import logger
logger.add("debug.log", level="DEBUG")
```

### Q2: 如何限制用户访问？

使用 `allowFrom` 白名单：

```json
{
  "channels": {
    "telegram": {
      "allowFrom": ["user_id_1", "user_id_2"]
    }
  }
}
```

### Q3: 如何处理大文件？

使用流式处理或分块：

```python
# 分块读取
with open(large_file, "r") as f:
    for chunk in iter(lambda: f.read(4096), ""):
        process(chunk)
```

### Q4: 如何优化响应速度？

1. 使用更快的模型（如 Haiku）
2. 减少上下文长度
3. 缓存常用结果
4. 使用本地模型

### Q5: 如何扩展到多用户？

nanobot 原生支持多用户：

- 每个用户有独立的 session
- 使用 `session_key = f"{channel}:{chat_id}"` 区分
- 会话数据存储在 `~/.nanobot/sessions/`

### Q6: 如何备份数据？

备份这些目录：

```bash
~/.nanobot/
├── config.json      # 配置
├── workspace/       # 工作区
├── sessions/        # 会话数据
└── history/         # 命令历史
```

### Q7: 如何贡献代码？

1. Fork 仓库
2. 创建功能分支：`git checkout -b feature/my-feature`
3. 提交更改：`git commit -m "Add my feature"`
4. 推送分支：`git push origin feature/my-feature`
5. 创建 Pull Request

### Q8: 性能优化建议？

- 使用 `restrict_to_workspace` 减少文件扫描
- 限制 `max_iterations` 避免无限循环
- 使用 `filter_unavailable` 过滤不可用技能
- 定期清理旧会话数据
